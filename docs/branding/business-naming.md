## What it does

`business-naming` runs a naming project the way a professional naming agency describes its process. It does not stop at a list of names. It writes a short creative strategy and sends three independent teams to generate names from different angles: insiders, a "twist" team and outsiders who never see the real product. A separate judge, who didn't make any of the names, judges them. Shortlisted names go through preliminary language and trademark screens, and the finalists are shown on a visual board in realistic context (headline, ad line, descriptor).

It writes its working files to a `naming-<slug>/` project folder, so you can see every stage, from research to the final board and report.

## When to reach for it

Reach for it whenever you need a name for a company, product, app, feature or service, or you're stuck choosing between names you already have. You don't need to call it by name. "What should I call this?" is enough.

It also covers three smaller jobs:

- **Judging names you already have.** It skips generation and goes straight to scoring, screening and the board.
- **Deciding whether to rename.** It starts by testing whether a rename is worth it.
- **A descriptor or tagline** for a name you've already chosen.

Say "quick" if you want a faster run with smaller quotas.

It is not for naming variables, files or other code identifiers.

## It's working if

- The strategy checkpoint makes you disagree with something. That's the cheapest moment to redirect.
- The finalists include a few names that make you a little nervous. A set nobody objects to is usually forgettable.
- You can see why each finalist was chosen, and which names were set aside rather than thrown away.
- The report says plainly that trademark and domain checks are preliminary.

## Common questions

**Are the trademark checks legal clearance?**
No. They're knockout screens to catch obvious conflicts early. Before spending money on a name, have an IP attorney clear it in each market you care about.

**Why so many names?**
A long list is cheap now. The value is in generating far past the obvious names and then judging strictly in a separate step. Most of the names are meant to be discarded.

**I hate one of the finalists. Should I ask for it to be removed?**
Say what bothers you. The skill turns objections into a brief ("less clinical", "easier to spell") and can run a small targeted round. Strong names that get rejected are moved off the table for now, not deleted.

**Does it need subagents?**
It runs best with them, because the teams and the judge are meant to be independent. Without subagents it plays each role in sequence and keeps generating and judging as separate steps.
